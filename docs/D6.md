# D6. Test Case Design

## Skenario yang dipilih
**S2. Mengerjakan Simulasi dan Menerima Feedback** (lihat [D4](D4.md)).

Skenario ini dipilih karena memuat fungsi `evaluate_simulation` yang diuji di D7, dan karena paling banyak punya kondisi batas serta input tidak valid.

## Aturan Bisnis yang Diuji
Aturan ini dipakai sebagai dasar semua test case dan harus sama dengan implementasi D7.

| Aturan | Nilai |
|---|---|
| Persentase | `correct / total × 100` |
| Status **Siap** | persentase ≥ 80 |
| Status **Hampir Siap** | persentase ≥ 60 dan < 80 |
| Status **Perlu Latihan Lagi** | persentase < 60 |
| Input valid | `total` bilangan bulat > 0, dan 0 ≤ `correct` ≤ `total` |
| Input tidak valid | ditolak dengan error, tidak ada hasil yang disimpan |
| Kirim jawaban | semua task wajib terjawab, dan satu attempt hanya boleh dikirim sekali |

**Ringkasan:** 6 test case common (TC-01 sampai TC-06) dan 9 edge case (TC-07 sampai TC-15), total 15.

## Cara Memilih Edge Case
Edge case dipilih dari kategori yang diminta spec dan disesuaikan dengan aturan bisnis simulasi. Kondisi batas (TC-07 sampai TC-09) diambil dari titik pindah status, yaitu persentase 80 dan 60, karena kesalahan "lebih besar atau sama dengan" sering muncul di sana. Nilai ekstrem (TC-10), input kosong (TC-11), limit (TC-12), dan format tidak valid (TC-13) dipilih karena langsung menguji validasi fungsi dan form. Kasus duplikat (TC-14) dan kegagalan sistem (TC-15) berasal dari alur alternatif di sequence diagram S2, sehingga test case dan diagram saling cocok.

## Test Case yang Dapat Dijadikan Unit Test (D7)
TC-01, TC-02, TC-03, TC-07, TC-08, TC-09, TC-10, TC-12, dan TC-13 bisa langsung diuji pada fungsi `evaluate_simulation`. TC-04, TC-05, TC-06, TC-11, TC-14, dan TC-15 melibatkan UI atau database sehingga tidak masuk unit test D7. Catat nomor TC yang dipakai di komentar tiap unit test.
